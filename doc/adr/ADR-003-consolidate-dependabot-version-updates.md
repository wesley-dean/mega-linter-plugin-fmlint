# ADR-003: Consolidate Scheduled Dependabot Version Updates

Date: 2026-11-12

## Status

Accepted

## Decision

Retain the existing weekly Dependabot version-update schedule for both
`github-actions` and `pip` ecosystems. Give each ecosystem its own
wildcard `applies-to: version-updates` group, without an `update-types`
restriction: `actions-version-updates` and `pip-version-updates`.
Apply `cooldown.default-days: 7` to each routine version-update entry.
Eligible major, minor, and patch versions may be grouped within their
own ecosystem; no cross-ecosystem grouping is intended.

Dependabot security updates remain independent and must not be
delayed or bundled into these routine groups. Keep the existing
`dependabot/fetch-metadata` auto-merge condition, which excludes groups
whose highest semantic-version change is major. A major-containing group
must undergo targeted manual review before it can be merged.

## Context and Decision Drivers

The current configuration schedules both ecosystems weekly, grouping
minor and patch versions only, with no cooldown. Major updates may
therefore create separate PRs while routine updates arrive frequently.
The verified `coding_standards@v3.2.0` release recommends broad routine
version groups by ecosystem and a seven-day cooldown to reduce repeated
maintenance reviews without weakening security response.

This plugin's Bash adapter extracts YAML frontmatter from Markdown
before yamllint. ADR-001 governs extraction semantics, public
`MARKDOWN_FMLINT` and `.fmlint.yml` compatibility, diagnostics,
and tests. ADR-002 requires source-commit-pinned descriptor runtime
downloads and a validation-before-publication release boundary.
The root `requirements.txt` is generated by pip-compile, pins Python
packages and carries hashes, so a pip update must preserve resolvable,
verified hashes and tested frontmatter lint behavior.

## Assumptions and Constraints

- These are the two already configured Dependabot ecosystems; no others
  are enabled by this decision.
- The weekly schedule and distinct package-ecosystem scopes remain.
- The existing non-major-only automatic merge policy is unchanged;
  neither workflow nor pip major-containing groups qualify.
- Pip dependency updates must keep hash integrity and must not claim
  lockfile correctness without inspecting actual generated files.
- Effective CODEOWNERS review requirements, branch rules, Dependabot
  alerts and security-update settings require separate GitHub verification.
- The published plugin descriptor, runtime package versions, Bash code,
  test fixtures, workflow permissions, and release contracts do not change.

## Alternatives Considered

1. **Retain minor/patch-only grouping.** Rejected as the default because it
   keeps major-version PRs separate without increasing the required review.
2. **Group major, minor, and patch per ecosystem.** Chosen to reduce routine
   PR fragmentation while preserving manual scrutiny for major upgrades.
3. **Combine GitHub Actions and pip in one group.** Rejected because their
   compatibility, dependency-resolution, and trust boundaries differ.
4. **Ignore the pip ecosystem because requirements are hash-pinned.**
   Rejected because pinning does not remove the need for reviewed updates;
   incompatible or incorrect generated hashes must instead fail review.
5. **Use monthly scheduling or a longer cooldown.** Rejected until evidence
   supports a slower maintenance cycle.
6. **Auto-merge major-containing groups or close old PRs immediately.**
   Rejected: major compatibility risks and old PR replacement coverage
   require actual evidence.

## Tradeoffs and Consequences

Routine updates in each ecosystem may be represented by fewer proposals,
but no exact PR-count reduction is guaranteed. Resolver conflicts or
incompatible versions can produce multiple PRs or failures; isolating a
problem dependency requires an explicit reviewed exception, not hiding
updates with an `ignore` rule. Seven-day cooldowns affect routine
version updates, not independent vulnerability remediation.

Every grouped PR requires review of each changed dependency, especially
GitHub Actions with write authority and pip packages used by yamllint.
A major-containing group requires release-note, migration, permission,
generated-hash, and behavior-level evidence appropriate to its highest
risk. Linter success alone does not establish packaging or publish safety.
Existing Dependabot PRs #71 and #87 remain open until a later update
demonstrably covers their dependencies and passes suitable verification.

## Expected Outcomes, Verification, and Compatibility

Observe the next scheduled Dependabot run for each ecosystem, confirm
the wildcard grouping and cooldown, and inspect actual auto-merge metadata.
Verify CODEOWNERS/required checks and security-update enablement
independently; repository YAML does not establish those controls.
Compare PR volume and review effort over time rather than promising
a particular reduction.

This decision does not change frontmatter behavior, executable adapters,
runtime packages, release artifacts, or published API compatibility.

## Related Decisions

ADR-001 governs the frontmatter extraction and lint interface. ADR-002
governs exact-source descriptor artifacts and separation of privileged
release publication. Neither is superseded by this maintenance decision.
